### 5.1. Флагман — Yat / yatledger

**Название:** Yat / yatledger

**Описание:** распределённая финансовая система на основе DAG.

Yat — экспериментальный проект открытого реестра для учёта ценностей, прав и обязательств. В основе архитектуры — граф транзакций (DAG), криптографическая проверка операций и распределённое серверное ядро.

Автор самостоятельно проектирует архитектуру и реализует основные компоненты системы: от серверной части на Rust до клиентского веб-кошелька.

**Технологии:** Rust, JavaScript, Raft, DAG, Ed25519, Vue, Quasar.

**Статус:** работающие компоненты, экспериментальный проект.

**Репозиторий:** https://github.com/yatledger

Крупный флагманский блок. В раскрытом состоянии показываются краткое описание архитектуры и ссылки на серверную и клиентскую части, если они доступны в репозитории.

### 5.4. Требования к расширяемости каталога

Каталог проектируется как список однотипных элементов данных, а не как набор вручную свёрстанных уникальных карточек.

Для каждого проекта предусмотреть следующие поля:

- `id` — уникальный идентификатор.
- `title` — название проекта.
- `summary` — короткое описание.
- `description` — необязательное развёрнутое описание.
- `website` — необязательный URL сайта.
- `repository` — необязательный URL репозитория.
- `featured` — признак крупного или выделенного проекта.
- `layout` — вариант отображения: флагман, сетка или компактный каталог.
- `details` — необязательные материалы раскрытого кейса.
- `order` — порядок отображения.
- `active` — возможность временно скрыть проект без удаления данных.

Поля `website` и `repository` независимы друг от друга. Проект может иметь сайт и репозиторий, только сайт, только репозиторий либо не иметь ни одной публичной ссылки.

Добавление проекта не должно требовать изменения HTML-шаблонов или создания отдельной страницы. Достаточно добавить новую запись в данные каталога.

Неизвестные URL хранить как пустые значения, а не как фиктивные адреса.

При пустом `website` или `repository` соответствующее место в структуре элемента сохраняется, но пустая ссылка не должна выглядеть кликабельной. Визуально слот может быть скрыт, а сетка и остальные элементы должны оставаться целыми.

Если позднее появится сайт для проекта, его можно добавить в поле `website` без изменения структуры карточки.

Не загружать описания проектов из внешних источников при каждом открытии страницы. Контент задаётся локально в проекте сайта; внешние ссылки ведут на исходные сайты и репозитории.
